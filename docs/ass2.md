# Alternate Scarlet Symphony -Final- tab

[← Back to the README](../README.md)

The **Alternate Scarlet Symphony -Final-** tab presents the mod: its features, every gameplay hack, screenshots, and downloads.

- **Download the PPF.** `ass2/ASS-Final.ppf` is a PPF3 from the US Track 1 BIN to ASS -Final-. It has a block check and undo data, so PPF3 patchers can verify the input and undo it. The tab lists the input, output and patch SHA-256 hashes. The download is named `ASS-F.NN.ppf` after the build.
- **Build it here.** Open the vanilla US Track 1 with **Open SOTN BIN**. The tab compares every patched region with the patch's undo bytes, so it says whether the BIN is untouched vanilla, already ASS -Final-, or something else. **Build** prepares the patched image in 8 MB windows and verifies the release CRC32 before opening the destination dialog. ASS -Final- already carries its title below the Symphony of the Night logo and `https://pddmergilla.github.io/sotn-editor/` at the bottom left, so the browser build adds nothing to the title screen and matches the release exactly. In Chrome/Edge, enter an output name and choose its folder; any existing destination, including the loaded vanilla BIN if selected, receives a unique verified `.sotn-backup` before replacement. The backup is deleted only after every saved byte is checked. Failed writes or checks retain it and report its name. Download-only browsers cannot manage these backups or verify files on disk. Open edits remain available after replacement; unsaved editor changes are not included in this release build. A `.cue` that pairs the new Track 1 with the vanilla Track 2 can be downloaded.
- **Release data.** The hashes, sizes and headline counts on the page come from `ass2/ass2-release.js`, and the hack list comes from the Extra Hacks catalog, grouped by category. After changing the main BIN, rebuild the separate patches, the catalog and the release (see [the -Final- changes](final-hacks.md)):

  ```text
  node tools/ass2/build-final-hacks.js
  python tools/extra-hacks/build_catalog.py
  node tools/ass2/build-release.js [--vanilla PATH] [--ass PATH]
  ```

  The release builder reads the main BIN in `MainBIN/` by default and checks that the PPF turns vanilla into it byte for byte. Most of the patch is the Form 2 (XA/STR) sector EDC, which differs in about 175,000 sectors. Keeping it makes the result an exact copy of the main BIN.
- **Build number.** Each release has a build number, shown as **ASS-F.NN** in the Get it section, on the download button, and in the downloaded file name (`ASS-F.NN.ppf`). It is also written into the PPF description. `build-release.js` starts at F.01 after the 2.0 builds (ASS 2.0.01–2.0.10) and raises it by one whenever the main BIN differs from the one the previous release was built from. `--build N` sets it directly.
- **Current build: ASS-F.01.** The first -Final- release: vanilla to main BIN `88B80D57…` (rebuilt as F.01 before release after the last balance and bug fixes, which also moved subweapons to the spell INT formula). 32 new hacks on top of the 30 from ASS 2.0 (including the -Final- stats and castle as one hack each), with Richter always saved finished and on. The PPF reproduces the main BIN exactly, including its -Final- title artwork.
- **Download counts.** The Get it section adds up tracked PPF downloads across every numbered release, ASS 2.0 builds (tag `ass2-v2.0.NN`, `Alternate-Scarlet-Symphony-2.0.NN.ppf`) and ASS -Final- builds (tag `ass-vF.NN`, `ASS-F.NN.ppf`), so a new build does not reset the total. It reads every page of GitHub's release history and counts each matching uploaded PPF once. The current build's download links separately require a matching name, size and SHA-256; an unpublished build uses the website copy while still showing the historical total. If the history cannot be read in full, the count shows "Download count unavailable." Counts cover all GitHub release tracking from its beginning, excluding browser builds, fallback downloads and earlier untracked website downloads; those earlier downloads cannot be recovered, and downloads are not unique players.
- **Publishing.** Commit and push these changes to `main`. The **Publish ASS -Final- downloads** workflow publishes the current numbered PPF, then runs automatically when the patch or release data changes. You can also run it from GitHub's Actions tab on `main`. It uses GitHub's built-in token; no extra secret is needed. The workflow verifies the shipped patch against the release data before publishing and leaves matching attachments untouched on reruns to preserve their counts. If an existing build has different bytes, increase the build number rather than replacing its attachment. Keep earlier release attachments: the website adds their counts to the total.
- **Private site counts.** `site-stats.js` counts page visits, ASS PPF download clicks (`download/ASS-F.NN.ppf`), browser builds of the release (`build/ASS-F.NN`) and editor exports (`editor/build-bin`, `editor/export-ppf`) with [GoatCounter](https://www.goatcounter.com). The counts are anonymous, use no cookies, include nothing from the user's BIN, and appear only in the owner's GoatCounter dashboard (keep its public-viewing setting off). Counting stays off and loads nothing until `CODE` in `site-stats.js` holds the GoatCounter site code; GoatCounter ignores localhost. When it is switched on, say so in the README's privacy paragraph.
- **Screenshots.** Put images in `ass2/screenshots/` and list them in `ass2/screenshots/screenshots.json` as `[{"file": "castle.png", "caption": "...", "source": "..."}]`. Use `"url"` instead of `"file"` for an image hosted elsewhere. It currently holds the four ASS 2.0 screenshots. The gallery stays hidden while the list is empty.
- **Copy.** Feature text describes the changes without exact values; those live in the Stats Editor and Extra Hacks tabs. Blue Metalmorphosis is described without its input on purpose, and the Life Apple revive is left out of the page as a surprise. The page has no hack list or count; the Extra Hacks tab lists them.
- The build needs the page served over http (`node serve.js` or the hosted editor). From a `file://` page only the download link works.
